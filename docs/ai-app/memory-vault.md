# 个人记忆库

把[统一聊天库](/ai-app/chat-ingest)蒸馏成结构化的「个人记忆资产」，供 Hermes 做备忘、日程和画像，
用 git 做版本管理，**推送前透明加密**，远端只存密文。

## 提取什么

| 目录 | 内容 |
|------|------|
| `journal/` | 每日日记：当天发生了什么、做了什么决定 |
| `people/` | 联系人画像：关系、约定、关键事件 |
| `profile/` | 自己的画像：偏好、习惯、长期目标 |
| `memo/` `schedule/` | 备忘与日程 |
| `tools/` | 提取脚本（明文） |

## 提取流程

- **大会话用 map-reduce**：按段分别提取，再合并，避免单次上下文超限。
- **全量回填可并发、可断点续跑**：几百天的历史一次跑不完，中断后从断点继续，不重复调用模型。
- **每日增量**：只提取前一天的新消息生成当天日记，画像按需重算。
- **噪音过滤**：Hermes 自己定时任务的输出、base64 长串等不是人说的话，提取前去掉，
  否则会被当成「当天发生的事」写进日记。

### 多平台裁剪要按配额，不能简单截尾

单日聊天超过上下文预算时，最初的做法是按时间排序后保留最后 N 个字符。
结果某个平台的消息集中在一天的某个时段，整段被截掉，日记里完全没有它。
改为**按平台分配配额、各自裁剪**，保证每个来源都有代表。

## 加密与版本管理

- 用 **git-crypt** 透明加密：数据目录在 `.gitattributes` 里标记加密，`tools/` 保持明文。
  本地是明文、正常编辑，推到远端自动变密文。
- **密钥导出一份放在仓库外并离线备份**——这是解开远端密文的唯一钥匙，丢了远端数据永久打不开。
- 推送前核对远端确实是密文，再推。

## 自动化

由 Hermes 的 cron 每天早上触发：

```
cron → 增量同步三平台聊天 → 提取昨天的日记 → 提交（自动加密）
```

只有需要人处理的失败才通知，不每天报「成功」。

## 边界

- 原始聊天、日记、画像只存在本机和加密仓库里，**不进任何笔记、不进对话记忆、不在终端打印**。
- 记忆是给自己的智能体用的，涉及他人的部分只保留与自己相关的关系和约定。
