# 广告投放助手

把 ERP 里选好的产品主图，批量做成 Meta 广告管理工具里的**草稿广告**：每个 SKU 复制模板广告组到一个新系列，
三级按规则命名，设好开始时间，换上主图和文案。**只生成草稿，不发布**，发布由人检查后手动完成。

运行在团队用的指纹浏览器里（每个广告账号一个独立浏览器环境），ERP 也登录在同一个浏览器里，
所以只需要一个插件，**不需要装 Python、不需要起任何服务**。

## 架构是怎么收敛的

| 阶段 | 方案 | 为什么放弃 / 采用 |
|------|------|-----------------|
| 1 | 走 Meta Marketing API 自动创建 | **否决**：API 的编辑权限包含预算调控，交给机器风险太大 |
| 2 | 官方「批量导入」表格 + ERP 侧小扩展生成导入表 | 能出草稿，但用户要在两个系统间来回导文件 |
| 3 | 本地服务 + 浏览器桥接扩展远程驱动页面 | 跑通了，但每台电脑要装 Python 起服务 |
| 4 | **纯插件**：ERP 取数和广告页操作都在同一个扩展里 | 采用，装好即用 |

## 安全边界（写死在代码里）

- **任何「发布」动作都不做**，测试也不点发布——那是真钱。
- 点击前检查落点文字，含「发布 / 放弃草稿 / 删除」的一律拒绝；弹窗内的点击需要显式放行。
- **禁止盲发 Esc**：在编辑页按 Esc 会弹「发布草稿内容？」。
- 同一广告账户同一时刻只跑一条任务，避免两条任务改同一批对象。
- 测试会创建真实草稿；清理必须核对精确的系列/广告组 ID，不能凭日志猜测删除。

## 驱动页面的技术点

- **用 `chrome.debugger`（CDP）操作页面**：文件上传框不能用脚本赋值，
  CDP 拦截文件选择框后注入本地图片；或在页面里构造 `DataTransfer` 注入。
- **不依赖坐标和脆弱位置**：广告平台界面经常改版、按钮位置在不同账号间也不同。
  选项按文字完全匹配去点，没渲染出来就滚动再找；大账户列表只渲染视口内的行，
  先用平台自带的筛选条件缩小列表再定位。
- **广告类型要识别分流**：帖子类广告不能改成普通广告，要走「创建帖子」路径，
  新旧两版发帖框各写一套。
- **平台弹窗内容会轮换**（比如「应用建议」每次推荐的项不同），不能假设固定第几项。
- **账户受限时保存永不结束**，等待最多 45 秒后继续，不卡死整条任务。

## 后台运行：最小化窗口里的定时器节流

用户希望跑任务时可以把浏览器最小化。实测发现：

- 窗口最小化约 **1 分钟后**，扩展页的定时器就被压到**一分钟一次**（不是之前以为的 5 分钟），
  导致某些步骤从几秒变成几十秒，甚至等待超时。
- 解决：CDP 的 `Emulation.setFocusEmulationEnabled` 让页面以为自己有焦点；
  **不仅被操作的广告页要开，跑流程循环的控制页自己也要开**，否则控制页本身被节流。
- 后台模式下不能调用 `tabs.update` / `windows.update` 抢焦点，否则会把最小化的窗口弹出来。

## 多账户并行与自愈

- 运行状态从全局变量改为**按任务的运行表**（账户、标签页、停止标记、各自日志），
  一个控制台可以同时跑多个账户，同一账户互斥。
- **每条任务一个独立执行页**：同一扩展的页面共享渲染进程，做不到系统级独立进程，
  但能做到每条任务一个后台标签页、互不阻塞。
- 执行页在每个产品每次尝试前检查自己负责的页面：被关了就重开、调试连接断了就重连、
  页面崩溃就刷新，8 秒探活无响应也刷新。
- **产品级自动重试**：单个产品失败重试，不影响同批其他产品；
  重试前先查是否已经复制出同名草稿，**按 ID 跳过已创建的**，避免重复创建。
