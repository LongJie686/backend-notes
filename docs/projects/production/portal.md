# 门户与统一鉴权

线上服务器上所有服务共用一个登录入口和一套权限：用户只在门户登录一次，
之后访问任何子服务都由 nginx 统一把关，**各服务自己的代码里没有登录逻辑**。

## 整体结构

```
浏览器 ──▶ nginx ──auth_request 子请求──▶ 门户后端 /api/auth/verify
            │                                （读 cs_session cookie）
            │  200 放行 / 401 跳登录 / 403 无权限页
            ▼
         各子服务（Gradio / FastAPI，只认「已经过网关」）
```

- **会话放 cookie 不放 Authorization 头**：cookie 设在主域上，所有子域和路径共享，
  nginx 子请求把原请求的 Cookie 透传给 verify 即可。
- **门户后端是 [CrossSail 看板](/projects/production/crosssail)兼任的**：它本来就有用户表和钉钉扫码登录，
  再加一个 verify 接口就成了全站鉴权中心。
- **子服务只负责「是谁」**：网关已经挡住未登录与无权限访问，子服务需要知道用户身份时，
  带着 cookie 回源 verify 取 id / 名称 / 角色，并做 60 秒进程内缓存，防止轮询把门户打满。

## 关键设计

### 401 和 403 必须分开

nginx 侧 `error_page 401 = @login`（302 去门户登录，登录后带回原地址），
`error_page 403 = @deny`（静态无权限页）。

如果「已登录但不是管理员」也回 401，用户会被送去登录 → 登录成功跳回原地址 → 又是 401 →
**重定向死循环**。所以后端必须严格区分：没会话 / 会话过期 = 401，身份确认但没权限 = 403。

不同原因的 403 用不同措辞（仅管理员 / 不在名单 / 无此服务权限），免得用户以为系统坏了。

### verify 单独限流

Gradio 页面一次加载几十个静态资源，每个都触发一次 auth_request。
verify 如果跟着全局 100 次/分钟的限流走，**一个人开一次页面就 429**，
而 auth_request 遇到 200/401/403 以外的状态码会直接对外抛 500。
解决：verify 从全局限流里排除，单独配一个宽松得多的限流器。

### 一张名单管所有门

每个服务一个 scope，nginx 用 `verify?perm=<scope>` 问一次，判权全部集中在门户一处：

| 模式 | 默认 | 名单里的行表示 |
|------|------|---------------|
| `open` | 放行 | `allow=0` 的人被封禁 |
| `list` | 拦截 | `allow=1` 的人放行 |

- 两种模式共用一张表、互不干扰：切模式不会把谁「反过来」误放误挡，切回去还是原状态。
- **管理员恒通**：既避免管理员把自己锁在门外，也让名单只表示「额外调整过的人」。
- **按 user_id 匹配，不按名字**：多数登录者是钉钉访客，昵称会改、会重名，
  按名字存迟早挡错人。
- **监控页的模式锁死在 list**：那里露成本和余额，一次误点就会把全公司放进来看账。
- 判权在热路径上（Gradio 轮询每次都过网关），模式表做内存缓存 + 写时失效 + 5 秒兜底 TTL。
  改名单即时生效，不用重启服务也不用让对方重新登录。

### 角色探针：前端也要知道权限

前端要决定侧边栏显不显示「全局监控」入口，但跨子域调门户会被 CORS 挡。
于是在每个子域下开一个**非 internal** 的同源 location 代理 verify（`?with=perms` 顺带返回可访问列表）。
它只返回当前会话自己的身份，没有越权面；真正的鉴权仍由 auth_request 把守。
`with=perms` 做成显式参数，不带参数的 verify 是热路径，不为它多查库。

### 内网服务的票据交换

部分服务跑在局域网的[辅助电脑](/projects/infra/aux-pc)上，浏览器直连局域网地址，带不上主域 cookie。
做法是门户签一张**短时效一次性票据**，跳转时带过去，内网服务拿票据回门户换成
指定 audience 的 JWT，之后用自己的会话。票据过期就提示「从门户重新进入」。

## 其他公共件

- **服务导航单一数据源**：各服务原本各自内嵌一份服务清单和侧边栏代码，加一个服务要改五处还常漏。
  收敛成门户托管的一个 `svc-nav.js`，各服务一行 `<script>` 引入；nginx 对它配 `no-cache`，
  浏览器每次带 ETag 校验，命中 304 只有几十字节。加载失败只是没侧边栏，不做降级副本，否则又会分裂成多份。
- **维护页**：`error_page 502 503 504` 指向品牌维护页，**保持 5xx 状态码**，
  前端据此轮询探测服务恢复，而不是把用户留在浏览器默认错误页。
- **全局监控页**：nginx 直接 `alias` 各服务的 `metrics.json`，监控页是纯静态 HTML 拉取汇总，
  不需要为它起服务。同样走名单网关。
