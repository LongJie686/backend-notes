# 辅助电脑

局域网里一台闲置台式机改的常驻服务器，承接从办公电脑迁出的内部服务。
没有公网 IP，需要对外的经线上服务器的反向隧道（见[总览](/projects/infra/)）。
每个服务一个子目录 + 独立 venv，开机由计划任务拉起。

## 服务一览

| 服务 | 形态 | 对外方式 |
|------|------|---------|
| 自建模型网关 | 开源 CLIProxyAPI + 自写守护/监控 | 办公电脑走正向隧道；线上服务走反向隧道 |
| 钉钉 AI 助手 | LangBot + 自研 Runner 插件 + 本地 Embedding | 钉钉 Stream（主动外连）；网页版经门户 |
| [字幕高亮](/projects/desktop/subtitle-karaoke) | Python Web 服务 | 局域网直连，门户中转页跳转 |
| 门户共享文件 | Python Web 服务 | 经门户 |

## 自建模型网关

给内部工具提供统一的 OpenAI 兼容端点，各工具不用各自管理模型凭据。
核心用开源 CLIProxyAPI，外面包了一层 Python：

- **守护进程**：管理中转、管理页、监控、隧道几个子服务，挂了自动拉起；
  只重载改动的子服务，其他进程不动。
- **监控页**：按使用方统计调用量，按时间窗口显示剩余额度和重置倒计时，未知值显示「未知」而不是 0。
- **冷却对账**：上游返回 429 后网关会按重置时间冷却该凭据；如果上游提前恢复了额度，
  网关里的冷却还在，就会出现「面板显示有额度、调度却说无可用」。
  解决办法是额度刷新后对账，确认各窗口都有余量时调管理接口清掉冷却。

排障先看错误码：全部是上游 `overloaded` 说明上游过载，网关本身没问题；
401 / 429 / 额度耗尽才是凭据侧的问题。

## 钉钉 AI 助手

公司内部的公共助手：员工在钉钉单聊或群里 @ 机器人，基于公司共享资料回答，支持图文。

- **底座用开源 LangBot**，钉钉走 Stream 模式——服务主动连钉钉，内网机器不需要公网回调地址。
- **自研 Runner 作为 LangBot 插件**：多 Agent 编排、工具调用、逐次模型调用记账与配额。
- **模型兜底**：主渠道重试 2 次，失败后切备用渠道 1 次；只对可恢复错误（连接失败、429、5xx）重试，
  **首个输出片段之后不再重放**，避免用户看到重复内容；已成功的工具调用不重跑。
- **Embedding 本地跑**：`bge-small-zh-v1.5` 的 CPU ONNX 版，无显卡也够用，不依赖外部嵌入接口。
- **知识库**：只索引管理员指定的共享目录，定时增量同步；个人记忆、私人文件按用户隔离，
  隔离靠数据层而不是提示词。
- **网页版**：门户配了主备两个上游，nginx `proxy_next_upstream` 自动切换。

## 运维约定

- **改动前双空闲确认**，和线上的 [safe_restart 空闲闸门](/projects/production/)同一原则。
- **只保存密钥路径**：隧道私钥只给系统账户可读；`authorized_keys` 用 `permitopen`
  限定隧道只能转发指定端口。
- 远程默认 shell 是 cmd，复杂操作用 `powershell -NoProfile -Command -` 从 stdin 喂脚本
  （多行代码块后要多一个空行才会执行）。
