# 自建模型网关

给内部工具提供统一的 OpenAI 兼容端点：开发工具、[创意对话](/projects/production/creative-chat)、
[钉钉 AI 助手](/projects/infra/dingtalk-assistant)都只认一个地址和各自的访问 Key，
不用各自管理上游凭据。部署在[辅助电脑](/projects/infra/aux-pc)上。

## 组成

核心转发用开源的 CLIProxyAPI（Go 写的单文件代理），外面包了一层 Python：

| 模块 | 职责 |
|------|------|
| supervisor | 守护中转、管理页、监控、隧道几个子服务，挂了自动拉起 |
| 管理页 | 上游凭据的授权录入；凭据交换和保存全部交给代理二进制，Python 不碰明文 |
| monitor | 按使用方统计调用、管理访问 Key、展示额度 |
| quota | 后台定时查上游额度，网页只读脱敏缓存 |
| proxy_guard | 本地代理端口缺失时拉起代理内核，不干预正在运行的代理 |
| client_tunnel | 其他机器上的客户端用，维持一条 `ssh -L` 隧道，保持原有访问地址不变 |

## 设计要点

### 访问 Key 只存指纹

每个使用方一个独立 Key。数据库只保存**加服务端密钥的 HMAC 指纹**，不存 Key 本身；
删除使用方时先撤销上游 Key 并确认移除，再标记删除，保留历史用量关联。

### 额度展示：未知就是未知

- 按时间窗口（短周期 / 长周期）显示剩余比例和重置倒计时；
  ≥30% 绿、0-30% 黄、0% 红。
- **读取失败显示 unknown / stale，不显示 0 也不显示「无限」**。上游只返回一个窗口时，
  另一个窗口写「未知」，不能当作没有限额。

### 冷却对账

上游返回 429 后，网关按 `resets_at` 给该凭据设冷却，期间不再尝试。但上游有时会**提前**恢复额度，
这时网关里的冷却还在，就出现「面板显示满额、调度却报无可用凭据」。

解决：每轮额度刷新后对账——冷却原因全是额度类、且各窗口剩余都 > 0 时，
调代理的管理接口清掉冷却。每个凭据 10 分钟最多清一次，失败只记日志；非额度原因的冷却不动。
改调度状态优先用管理接口，比停用再启用干净。

### 排障先看错误码

报 502 / 503 时，客户端看到的端口只是透传，要看网关主日志的错误码：

- **全部凭据都是 `overloaded`** → 上游过载，网关没问题，等恢复即可。
- **401 / 429 / 额度耗尽** → 才是凭据侧的问题。

## 迁移与运维

- 从办公电脑迁到辅助电脑：间隔 12 秒两次确认无调用 → 停旧 supervisor → 数据文件逐个比 hash →
  公网真实调用验证。客户端只是隧道目标变了，配置一行不用改。
- 开机由系统账户的计划任务拉起（开机 + 每分钟检查、实例已在则跳过）。
- 隧道私钥只给系统账户可读；`authorized_keys` 用 `permitopen` 限定只能转发指定端口，
  注意写 `host:port`，不能写 `none`。
- 改动只重载对应子服务，其他子服务 PID 不变。
