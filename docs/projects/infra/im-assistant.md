# 钉X AI 助手

公司内部的公共助手：员工在钉X单聊或群里 @ 机器人，基于公司共享资料回答，支持图文。
部署在[辅助电脑](/projects/infra/aux-pc)上，网页版经[门户](/projects/production/portal)对外。

## 选型：先找完整开源项目改造

原则是不从零写框架。对比了四个能接钉X的开源项目：

| 项目 | 适配点 | 判断 |
|------|-------|------|
| LangBot | 钉X Stream、管理界面、图文、原生知识库与访问控制；Apache-2.0 | **采用** |
| AstrBot | 钉X Stream、插件、FAISS 知识库；AGPL-3.0 | 群成员隔离键需修正，文件知识库更新缺同步 |
| QwenPaw | 完整个人 Agent、独立用户运行环境 | 普通单实例共享工具权限，公共入口按用户路由无证据 |
| AgentTeams | Manager/Worker、容器、文件共享 | 太重；Worker 隔离不等于同一 Worker 内的用户隔离 |

**钉X走 Stream 模式**：服务主动连钉X，内网机器不需要公网回调地址，也不用开入站端口。

## 架构：LangBot 做入口，自研 Runner 做执行

LangBot 保留已连通的钉X适配和管理后台，自研的 Runner 以 **LangBot 插件**形式接入，负责编排和执行。
设计上分七层：

1. **接入层**：钉X身份、消息去重、企业/员工/会话标识、AI 卡片更新。
2. **调度层**：全局与每人配额、同一会话整轮串行、超时、取消、公平排队。
3. **编排层**：指定 Agent、协调分派、并行、规划执行、固定任务链。
4. **能力层**：知识检索、图文处理、文件生成、业务工具，每个模块独立版本和开关。
5. **资源层**：共享模型客户端、连接池、嵌入模型；按授权范围和配置版本区分池键。
6. **数据层**：个人记忆、任务事件、费用账本，都有归属和保留策略。
7. **监控层**：流程、资源、成本、额度分开统计，错误能定位到具体某次调用。

**共享的是资源，不是状态**：模型客户端、连接池可以共享；带个人聊天状态的对象、
浏览器登录态绝不共享。多 Agent 组合**只能缩小或继承请求者权限，不能通过组合扩大权限**。

## 首轮参数（保守起点，压测后再放大）

| 项 | 初始值 | 说明 |
|----|-------|------|
| 全局同时执行 | 2 | 压测后逐步到 4 / 8 |
| 每人同时执行 | 1 | 同一会话整轮串行 |
| 单请求参与 Agent | ≤ 4 | 并行调用也受全局配额约束 |
| 共享实例缓存 | 闲置 10 分钟、最多 8 个 | 正在用的不回收，满了先淘汰闲置 LRU |
| 单任务超时 | 默认 120 秒、最长 300 秒 | 长作业改后台任务 + 进度 |
| 流事件队列 | 32-64 条，有界 | 客户端慢时施加背压，不无限积压 |
| 心跳 | 5 秒 | 表示仍在处理，不是虚构进度 |

资源池用**租借计数**：最后一个任务归还后才开始计 TTL；配置或授权变更生成新池键，
旧实例空闲后回收；撤权立即禁止新租借。

## 模型调用：兜底不能导致重复

- 主渠道重试 2 次，再切备用渠道 1 次；只对可恢复错误（连接失败、429、5xx）重试，
  上游给了很长的 Retry-After 就直接跳到备用渠道。
- **首个输出片段之后不再重放**，否则用户会看到重复内容；已成功的工具调用不重跑。
- **每次真实模型尝试单独记账**（调用 ID、渠道、token、价格版本），父子任务汇总时不重复计费；
  未知单价显示「未配置」，**不显示为 0**。
- 发消息、写业务数据这类有副作用的操作必须带幂等键和回执，超时后禁止盲目重试；
  取消本地等待不等于撤回了外部操作。

## 知识库同步：宁可不删，不能删错

管理员指定一个共享目录，定时增量同步到知识库：

- 按 SHA256 判断新增和修改；文件类型白名单，单文件有大小上限。
- **「索引完成」不等于「可检索」**：只有检索结果里能命中该文件的内容，才算验收通过。
- **新版本验收通过才删旧版本**；状态不确定（上传结果未知、任务记录丢失）时保留原记录，不盲目重传。
- **删除有闸门**：源目录为空时不批量删；单次最多删 5 个且不超过总数 20%，超了必须人工核对清单。
- 状态写入 manifest，用临时文件 + 原子替换；同一个知识库只允许一个同步主机，靠文件锁互斥。
- 中断后再跑会从 manifest 续上；任务接口查不到时回查持久文件列表，防止服务重启后重复上传。

案例类资料（结构化的审核记录）不走向量检索，单独建 **SQLite FTS5** 全文库，
保留原始标签、备注和来源行号，检索结果能追溯到原表哪一行。

## Embedding 本地跑

`bge-small-zh-v1.5` 的 CPU ONNX 版，512 维，无显卡也够用，不依赖外部嵌入接口——
模型网关只提供对话接口，嵌入接口不在其中。

## 文件怎么回传给员工

插件生成的文件（如 DOCX 报告）不能用 base64 塞进回复：插件结果有约 1 MiB 上限，
500 KB 的 DOCX 经 base64 膨胀再加信封几乎必然超限。正确做法是**在最终消息里放文件 URL 组件**，
由 LangBot 主程序在结束时下载并上传钉X——URL 必须是主程序可达的地址，
插件只在回环地址上提供只读下载。

## 隔离与验收

- 身份键 = 企业 + 员工；私聊长期记忆与群上下文分开；**隔离靠数据层，不靠提示词**。
- 员工不能在请求里自己指定别人的 user_id 来拿权限；含个人内容的答案不做跨用户缓存。
- 验收必须用真实企业应用和两名真实员工互测（互相读不到对方资料和记忆），
  **管理后台的健康检查通过不能当作「已上线」**。
