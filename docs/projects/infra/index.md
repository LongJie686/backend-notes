# 本机与内网服务

除了跑在香港云服务器上的[生产工作流](/projects/production/)，还有两台机器常驻服务：
本机（日常开发电脑）和内网服务器（公司局域网里一台闲置台式机改的常驻服务器）。
三台机器的分工如下（2026-11-03 现场核对）：

| 机器 | 定位 | 主要服务 |
|------|------|---------|
| [本机](/projects/infra/local-pc) | 开发 + 个人 AI 助手 | Hermes 网关（WSL）、Claude Code 周边守护进程、号池客户端隧道、本地采集任务 |
| [内网服务器](/projects/infra/lan-server) | 公司内部常驻服务 | Codex 号池、钉钉 AI 助手、字幕高亮、门户共享文件 |
| 香港云服务器 | 对外公网入口 | 7 套生产工作流 + 统一门户，见[生产工作流](/projects/production/) |

## 机器之间怎么连

```
                         香港云服务器（公网入口，nginx）
                          ▲ 反向 SSH 隧道（-R）
                          │ 18317-18319  号池（创意对话、号池监控用）
                          │ 18540/18544  WebChat（/assistant/ 主备）
                          │ 18543        门户共享文件
                          │
本机 ──正向 SSH 隧道(-L)──▶ 内网服务器
127.0.0.1:8317-8319        8317 号池中转 / 8318 授权页 / 8319 监控
```

- **机器之间走 Tailscale**：内网服务器没有公网 IP，本机和它之间的 SSH 都走 Tailscale 组网；
  同一局域网时 Tailscale 会自动打洞直连。
- **内网服务对外靠反向隧道**：内网服务器主动连云服务器，把自己的端口映射到云上的
  `127.0.0.1:185xx`，再由 nginx 反代 + 门户鉴权。云服务器上这些端口只监听回环，不直接暴露。
- **本机用号池靠正向隧道**：本机的 ccs / DSH 等客户端只认 `127.0.0.1:8317`，
  `client_tunnel.py` 维持一条 `-L` 隧道把它转到内网服务器，号池换机器时客户端配置不用动。

## 服务迁移的经验

2026-10-20 把号池、字幕高亮从本机迁到内网服务器，几条通用做法：

1. **每个服务独立 venv**，共享一份基础 Python（`runtime/Python311`），互不影响。
2. **开机自启用 SYSTEM 计划任务**（开机触发 + 每分钟检查，IgnoreNew），不依赖有人登录。
3. **切换前做双空闲确认**：间隔 12 秒两次确认无调用，再停旧进程；
   数据文件逐个比对 hash 一致后才以新机为准，旧数据保留作回退。
4. **端口和消费者不变**：迁移只换隧道的目标机，客户端看到的地址不变，迁移对使用方无感。
